Kaushik PG — Admin + Tenant Apps — Current State

Scope: Two Flutter apps sharing one Firebase project. Admin app (owner/manager):
tenant management, room/bed inventory, rent tracking with configurable due date
& penalty, tenant document vault + verification, payment claims review, rent
receipt generation, reports, activity log, maintenance ticket triage,
broadcasts. Tenant app: view dues/payment history/receipts, pay via a static
UPI QR code and upload a screenshot as proof, upload ID documents, raise
maintenance tickets, receive announcements and push notifications. Android
only so far; iOS not yet built.

        +------------------+-----------------------+ sendPendingReminders)

                           |
              +------------+-------------+
              |                          |

      (due reminder,               (optional — staff
       payment approved/           FCM tokens are
       rejected, broadcast,        registered)

Auth model: custom claims are the source of truth for both Firestore and
Storage security rules — not cross-service Firestore lookups from Storage
rules (that pattern proved unreliable; see the read/write permission
distinction note below). `staff` is set by the onStaffWritten trigger
whenever a /staff doc is written; `tenantId` is set by provisionTenantLogin
when the owner generates a tenant's login.

Key lesson baked into storage.rules: `allow read` and `allow write` are
evaluated completely independently. Any upload flow that calls
getDownloadURL() right after uploading needs an explicit read grant too, not
just write — a wide-open write rule alone does not fix an "unauthorized"
error if the read grant is missing.

3. Data Model (Firestore Collections, as built)

/pgs/{pgId}
  - name, address, totalRooms, staffIds[], paymentQrUrl

/roomTypes/{roomTypeId}
  - pgId, name, capacity (beds per room of this type), defaultRent

/flats/{flatId}
  - pgId, name, flatType (label only, e.g. "1BHK")

/rooms/{roomId}
  - pgId, flatId, roomTypeId, roomNumber, capacity

/beds/{bedId}
  - pgId, flatId, roomId, bedLabel, tenantId (null if empty)
  (one bed doc per capacity slot, created in a batch with the room; a bed's
  tenantId is the single source of truth for occupancy — no separate
  occupied-count counter to drift out of sync)

/tenants/{tenantId}
  - name, mobile, email, photoUrl, pgId, bedId
  - rentAmount, depositAmount, joinDate, status (active/exited)
  - documents: [{type, url, uploadedAt}]
  - verificationStatus (notSubmitted/pending/verified/rejected), verificationNote
  - authUid (set by provisionTenantLogin), fcmToken
  - emergencyContactName, emergencyContactPhone
  - exitDate, depositRefunded, exitNotes (set on checkout)
  - lastSeenBroadcastAt (tenant app's own read-tracking marker)

/payments/{tenantId_month}
  - tenantId, pgId, month ("YYYY-MM"), amountPaid, mode (cash/upi/bank)
  - markedBy (staff uid), markedAt, status (paid/pending/overdue)
  - penaltyApplied, receiptUrl (carried over from an approved payment claim)

/paymentClaims/{claimId}
  - tenantId, tenantAuthUid, pgId, month, receiptUrl, submittedAt
  - status (pending/approved/rejected), reviewedBy, reviewedAt

/maintenanceTickets/{ticketId}
  - pgId, tenantId, tenantAuthUid, tenantName, title, description, photoUrl
  - status (open/inProgress/resolved), createdAt
  - resolvedAt, resolvedBy, resolutionNote

/broadcasts/{broadcastId}
  - pgId, title, message, sentBy, sentAt
  (tenant-facing Announcements list only shows the last 24 hours — a notice
  board, not an archive; the admin's own Broadcasts screen keeps full history)

/settings/{pgId}
  - dueDate (default: 5), penaltyType (flat/percentage), penaltyValue
  - reminderDaysBefore, ownerName, contactPhone (shown on generated receipts)

/staff/{staffId}
  - name, role (owner/manager), assignedPgIds[], fcmTokens[]

4. Feature Status

Built and in use:
  - Tenant CRUD, PG/flat/room/bed setup with color-coded occupancy grid
  - Flat and room edit/delete (blocked while occupied/non-empty)
  - Tenant login provisioning (owner-generated email/password), staff login
    provisioning (owner-only, role + multi-PG assignment)
  - Manual "Mark as Paid" + tenant-submitted payment claims (QR + screenshot)
    with owner approve/reject
  - Tenant identity verification (email-verify gate, document upload, owner
    review)
  - Configurable due date & penalty settings per PG, daily scheduled penalty/
    reminder job, manual "notify pending tenants" trigger
  - Payment history / ledger per tenant, receipt view in the tenant app
    (amount, mode, date, and the original screenshot when approved via claim)
  - Rent receipt generation: 5 selectable PDF templates, share/print/save
  - Tenant exit/checkout flow: frees the bed, records exit date + deposit
    refund + notes, "Exited tenants" history screen
  - Admin activity log (who marked what paid / resolved which claim)
  - Reports: monthly collection %, pending dues with names, bed occupancy %,
    collected-by-mode breakdown
  - Broadcast/announcement system (owner publishes, all tenants notified;
    tenant-facing list expires after 24 hours)
  - Maintenance ticket system (tenant raises with optional photo, owner
    triages open -> in progress -> resolved)
  - Tenant-editable contact info (own mobile + emergency contact)
  - Sign-out confirmation in both apps
  - Production release signing (separate keystore per app, wired into the
    Gradle build; not yet published to Play Store)

Not yet built:
  - Expense tracking / P&L (Reports currently shows rent collected only, no
    cost side — electricity, staff pay, maintenance spend)
  - CSV/data export for tenants, payments, or reports
  - Pagination for tenant/payment lists (currently a single live stream per
    screen — fine at current scale, would need addressing well before
    5,000-tenant scale)
  - iOS build entirely
  - Play Store listing / actual publishing (signing is ready; store listing,
    screenshots, and the $25 registration are not done)
  - Kotlin Gradle Plugin version is pinned at 2.2.20 to keep firebase_auth
    compiling; Flutter's build output warns this floor is being deprecated
    and will eventually need revisiting alongside a firebase_auth upgrade
